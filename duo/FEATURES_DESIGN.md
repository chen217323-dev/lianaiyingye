# 《恋爱营业中》· 三个新功能交互设计（待确认）
版本：功能设计稿 1.0
状态：仅设计，尚未部署/迁移；现有双人云端网页保持原状。

## 现有约束
- 沿用 Supabase 项目和既有 `love_profiles` 身份：老公 owner、老婆 customer；各自用现有邮箱密码登录。
- 继续使用 `love_wallets` 和 `love_wallet_events` 作为唯一积分余额及流水来源，**不得**由前端直接修改积分。
- 色系延续奶油白、鼠尾草绿、浅杏黄，不使用大面积粉红。
- 当前手机底部导航已经有五项，不再强加三个导航按钮：从首页「甜蜜生活」三个入口进入，内页提供固定返回。
- 数据双方手机云端共享；私信正文仅发送双方可见。首期只做网页内角标和轮询/实时刷新，不承诺系统推送。

## A. 🎁 宠爱币商城
### 老婆端流程
1. 首页 → 宠爱商城 → 按分类浏览兑换券，可查看图片/emoji、积分、库存及使用说明。
2. 点击「兑换」→ 二次确认显示当前余额、需扣积分、兑换后余额，可选备注。
3. 经数据库原子扣积分、占库存并生成兑换单；页面出现「我的兑换券」，状态为「待老公兑现」。
4. 老公履约→「已兑现」；如老公不能兑现，可由老公发起退款，积分及库存按规则恢复。
5. 余额不足时提示「去赚积分」，不扣分；重复点击仅允许生成一笔有效订单。

### 老公端流程
「商城管理」里新增、修改、下架、删除或排序兑换商品；设置分类、积分、库存（可选不限量）、说明。另一页「待兑现」查看备注、标记已兑现或退款。

### 建议初始商品（积分均为可修改的示例）
- 🎬 今晚电影由老婆选：60◎
- ☕ 老公请喝一杯饮料：80◎
- 🧽 免洗碗券：100◎
- 🍳 专属爱心早餐：130◎
- 💆 15分钟肩颈按摩：150◎
- 🎁 老公准备小惊喜：200◎

### 规则
- 兑换立即扣积分、留下独立流水；价格在订单中快照保存，后续调价不影响旧订单。
- 兑换单 `pending -> fulfilled`；或 `pending -> refunded`。取消/退款必须幂等且只退一次。
- 可设置库存，不出售已下架或售罄商品；提交订单在数据库事务中检查余额与库存。
- 所有亲密类互动都以双方自愿为前提，积分兑换不等于强制任何身体接触。

## B. 🌳 两个人的愿望树
### 双方都能做
首页 → 愿望树：树叶卡片展示「想做什么」「谁写的」「日期」「状态」；筛选「全部 / 待认领 / 实现中 / 已完成」。

### 交互
- 点击「种下愿望」→ 写标题、愿望详情、可选分类（吃喝/出行/居家/小惊喜）与期望日期；免费，不消耗积分。
- 另一方点击「我来实现」→ 状态变「实现中」，作者收到站内提示；不需要积分。
- 实现后由写愿望的人点击「已实现」确认，卡片进入「回忆树」；可附一句回忆文字。
- 作者可以编辑尚未认领的愿望，双方可浏览；删除仅限作者的未认领愿望，已完成愿望可归档。

### 细节
- 进度文案温柔：`待认领`＝「一颗小小心愿」；`实现中`＝「有人正在悄悄努力」；`已完成`＝「今天也实现了一个愿望」。
- 默认不发积分，避免愿望变成任务买卖；实现后可以互相送一个免费的「♥」。
- 合照上传留待下一期（需要单独的 Supabase Storage 安全规则）。

## C. 📮 悄悄话信箱
### 两种写信方式
- 「现在送达」：写给对方，立刻在对方信箱出现未读。
- 「定时解锁」：选择时间（以韩国时间显示），到点才展示信件正文；提前只看到「有一封等待打开的信」。
- 双向：老婆可以给老公写，老公也可以给老婆写。

### 页面
- 信箱三页签：`收件箱`、`写一封`、`已寄出`。
- 卡片显示来信者、寄送时间、未读状态；打开后显示信纸阅读界面和「回一封」。
- 若信件延时解锁，显示剩余时间；通知先采用网页内角标与刷新，不承诺系统通知或微信推送。
- 首版支持文字与 emoji，限制每封约 1000 字；照片、语音、定时推送暂不做。

### 隐私与安全
- 仅已登录并属于两人账号的发件人与收件人能够访问对应信件。
- **延时信件正文必须由服务器按解锁时间控制可读**，不能仅在页面把文字隐藏；浏览器自行改时间也不应提前读取。
- 可由发件人撤回尚未被收件人阅读的信件；已读则留在双方信箱（永久删除策略待确认）。
- 普通 Supabase 存储不是端到端加密；数据库管理人员理论上可以读取存储的内容。界面不宣称「端到端加密」。

## 数据库预计新增
- `love_reward_items`：商品、积分、分类、库存、上下架、排序。
- `love_reward_redemptions`：顾客、价格快照、状态、创建/兑现/退款时间。
- `love_wishes`：作者、认领人、内容、状态、日期、归档。
- `love_letters`：发送者、接收者、正文、投递时间、解锁时间、已读与撤回状态。
- 受保护 RPC：兑换/退款、保存商品、发布/认领/完成愿望、发送/领取已解锁信件、标记已读等。
- RLS：所有新表对两位认证用户限定角色权限；兑换与退款只通过原子数据库 RPC 修改 `love_wallets` 与 `love_wallet_events`。

## 上线顺序与验收
1. 建表与权限、创建样例数据。
2. 上线「商城」：用小额积分测试扣减、库存、老公兑现/退款；确保账本数字不重复。
3. 上线「愿望树」：两端种愿望、认领、完成的同步测试。
4. 上线「悄悄话」：即刻发送、未来解锁、未读角标与访问权限测试。
5. 保留已有点菜、签到、任务审核、密码记住邮箱等功能不变；全部通过后再向双方提供更新后的正式链接。

## 待用户确认的默认行为
1. 商城：兑换时立即扣分、老公之后兑现；退款由老公操作。
2. 愿望树：完全免费，双方都能写愿望，提出愿望的人确认完成。
3. 悄悄话：双方都能写、可设解锁时间；默认只有文字，不做系统推送。
